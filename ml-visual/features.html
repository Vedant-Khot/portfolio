Feature Engineering — Spatial Kinematics & Physics Transformations

Disaster intelligence models live or die by the physical relevance of their features. Rather than feeding raw latitude/longitude pairs or skewed absolute area values directly to algorithms, this project applies rigorous spatial kinematics transformations, log compressions, and interaction terms — engineering 6 powerful derived features on top of the 31 sourced variables.

Domain Principle

In ML competitions and real-world disaster systems, good features often matter more than complex models. A well-engineered distance metric can outperform a deep neural network on raw coordinates.

Section 1 — Dataset Availability & Data Sparsity

A critical challenge: 72.4% of fires (160/221) have only a single perimeter snapshot in the first 5 hours. Because growth, movement, and kinematic features are computed as differences between perimeters, single-snapshot fires have definitionally zero values — encoding absence of data, not absence of fire expansion.

Section 4 — Engineered Feature Formulas & Physics

Engineered Feature 1
Log-Compress Distance
log1p(dist_min_ci_0_5h)
Correlation gain: −0.481 → −0.812 (+68.8%)

Starting distances range from 300m to 750km — three orders of magnitude. Raw distances cause linear algorithms to treat the 300–5,000m range as almost identical. Log compression expands this critical near-boundary region and compresses the far, safe region where all fires look the same.

Engineered Feature 2
Bearing Validity Flag
(spread_bearing_cos != 1.0).astype(int)
Eliminates −0.323 spurious artifact

72% of fires have only one perimeter snapshot. With no second measurement, the bearing defaults to 0° (North). This makes cos(0°) = 1.0 for all these fires — a completely fake signal. The model was learning "did we observe the fire enough times?" instead of "is the fire heading north?"

Engineered Feature 3
Observation Density
log1p(num_perimeters_0_5h)
Correlation: +0.371

High-risk fires generate many satellite alerts. Log1p linearizes the count distribution (1, 2, 3… → 0.69, 1.10, 1.39…). This also serves as the key segmentation variable separating the two modeling subpopulations. More perimeters = more kinematic data available.

Engineered Feature 4
Proximity × Speed
is_close × closing_speed_abs_m_per_h
Tier-1 alert amplifier

Multiplicative interaction between spatial proximity and closing velocity. Fires far away give zero regardless of speed. Fires that are close AND fast get the highest values — naturally encoding the "imminent threat" tier. Replaces the need for a manual rule-based alert system.

Engineered Feature 5
Spatial Hazard Alignment
log_dist_min × alignment_abs
Directional threat severity index

Combines how close a fire is with where it's heading. A fire 3km away heading directly at the zone (alignment=1.0) is encoded as log(3000)×1.0 = 8.0. A fire 3km away heading sideways (alignment=0.1) is 8.0×0.1 = 0.8. This encodes the joint threat level in a single, physically meaningful scalar.

Engineered Feature 6
Physics ETA Estimate
dist_min / max(closing_speed_abs, 0.1)
Correlation: −0.154 — Strongest timing predictor

Directly approximates the physical time-to-breach in hours, providing the survival model with its own target as an input feature for residual learning. Clipped at 72h (the maximum observation horizon). The max(..., 0.1) prevents division-by-zero for stationary fires.

Section 5 — Academic Traps, Artifacts & Fixes

Disaster risk forecasting is filled with mathematical traps. These two artifacts were identified and resolved to prevent the models from learning spurious or brittle patterns.

Trap 1 — Directional Artifact

spread_bearing_cos Default = 1.0

The Trap: When a fire has only one perimeter snapshot, no bearing can be computed — so the system defaults the angle to 0° (North). This makes cos(0°) = 1.0 for all 161 low-resolution fires, creating a false correlation of −0.323. The model was "learning" data availability, not actual wind dynamics.

✅ Fix Applied: Created bearing_is_real = (num_perimeters > 1) flag. Bearing features are masked to 0 when this flag is inactive. The model only uses directional data when it's mathematically valid.
Trap 2 — Perfect Separation Overfit

is_close = 1.000 Training Correlation

The Trap: In training data, every fire within 4,674m breached (100%). Using this as a hard threshold produces extreme probabilities (0 or 1), severely damaging calibration when test fires appear in the 4,674–5,000m gray zone — a distance range that has zero training samples.

✅ Fix Applied: Force continuous log1p(dist_min_ci_0_5h) as the primary input. The model learns a smooth logistic boundary — outputting calibrated non-binary probabilities near the 5km threshold, not hard decisions.
Trap 3 — Data Leakage

Percentile Scaling Across Full Dataset

The Trap: Computing standard scaling or percentile normalization over the combined train+test dataset leaks test statistics into the training loop, inflating validation accuracy by up to 3–4 C-Index points. Many Kaggle models make this mistake.

✅ Fix Applied: All percentile features and Robust Scaler normalization parameters are fitted strictly on the training split, then applied to test as frozen mathematical constants — never refitted on test data.
Trap 4 — Sparsity Pooling

Naively Pooling High/Low Resolution Fires

The Trap: Simply merging single-perimeter (72.4%) and multi-perimeter (27.6%) fires into one model pool dilutes the kinematic signal — the dynamic features are all zero for the majority class, making them appear uncorrelated with the event even though they're highly informative within the multi-perimeter subpopulation.

✅ Fix Applied: Always include low_temporal_resolution_0_5h indicator as both a direct feature and a model stratification variable. The 60.7% breach rate in multi-perimeter fires vs 20.0% in single-perimeter fires demands subpopulation-aware modeling.
